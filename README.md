# Sipan · سیپان

Sipan is a native Android browser for reading web pages, manga, manhwa, webtoons and menus in your own language. Sipan upgrades the signed RojInk and Sipan releases with the same Android application ID and signing key. Tap **Paste & open** (or enter a link), then **Translate → Start translation**, and Sipan uses Google Translate for page text and recognized text inside images. **کوردیی سۆرانی (Sorani Kurdish, `ckb`)** is the default target. Open **Try a sample page** on the home screen to try a built-in panel and a menu.

**بۆ دەستپێکردن:** لینکی مانگا یان مانهوا دابنێ. کاتێک پەڕەکە بار بوو، **Translate → Start translation** هەڵبژێرە. زمانی بنەڕەتی وەرگێڕان کوردیی سۆرانییە. بۆ گۆڕینی زمانی ڕووکاری ئەپ، لە سەرەتای ئەپ **کوردی** هەڵبژێرە.

## Install the APK without Android Studio

1. On your Android phone (Android 8.0 or later), download **sipan-signed-release.apk** from [Sipan releases](https://github.com/s1po0/Browser-translator/releases/latest). The public APK download does not require a GitHub account.
2. Open the `.apk` directly in Files. If Android asks, allow installation from the file manager you just used. You can turn that permission off again afterwards. Development builds remain in [GitHub Actions](https://github.com/s1po0/Browser-translator/actions/workflows/build-apk.yml?query=branch%3Aarena%2F1fef4dd4-browser-translator), which may require signing in; `translating-browser-debug.apk` is not the update for a signed installation.
3. Open **Sipan**. Use **Paste & open** on a copied link, type in the address bar, or try the sample page. Tap **Translate → Start translation**. Scroll for newly visible panels. Hold a translated image to peek at the original, or use **Show original** for the whole page. To save an original web image, switch to **Show original**, then long-press the image.

The debug APK is for testing (`dev.rojink.browser.debug`). GitHub's clean runners use debug signing keys, so a build from another run may not install over a previous debug build. Export bookmarks before uninstalling a debug build. Use the **signed release** APK (`dev.rojink.browser`) to update a signed RojInk or Sipan installation in place. Do not uninstall it first. The database migration keeps bookmarks, history, download records and the text cache.

## Release signing and key custody

**Do not commit or share the keystore, key passwords, or an unencrypted export.** If you already have a release key for `dev.rojink.browser`, keep using it. For the first release, generate an Android-compatible signing keystore in a trusted, private environment. Keep an independent encrypted backup in a vault you control; **GitHub Actions Secrets cannot be read back** as a backup. Store the passwords with the backup, not in the code or in chat.

The optional offline tool in `tools/signing-key/` can generate a protected `.p12` and copy-ready values locally. It can also re-encrypt a previous RojInk/Sipan export without changing the signing identity. To build it, run `npm ci --prefix tools/signing-key --ignore-scripts` and `npm run build --prefix tools/signing-key`; the generated HTML contains no saved keys and is ignored by Git.

Use the repository's **Settings → Secrets and variables → Actions → New repository secret** page (or authenticated `gh secret set` outside chat):

| Secret | Value |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | The contents of your `.jks` or `.p12` keystore, base64-encoded (base64 is **not** encryption) |
| `ANDROID_STORE_PASSWORD` | Keystore password |
| `ANDROID_KEY_ALIAS` | The signing certificate's alias |
| `ANDROID_KEY_PASSWORD` | The signing key's password (often the same as the store password for PKCS#12) |

On `arena/1fef4dd4-browser-translator`, a trusted push whose head commit message contains `[signed-apk]` requests a signed build. Regular pushes only build the debug APK. When the workflow is on the default branch, you can also go to **Actions → Build Android APK → Run workflow** and check **Also build the signed release APK**. The signing step reconstructs the keystore in a temporary file, deletes it at exit, verifies the APK with `apksigner`, and uploads **sipan-signed-release.apk**. Keep the same app ID and key for future releases; successful runs increase the APK version code with the workflow run number.

For a public download, after the signed build and Android smoke tests pass for the same commit, push a commit with `[publish-apk:BUILD_RUN_ID]` on its own message line. Use the numeric ID from the signed build’s `/actions/runs/…` URL. The publish workflow verifies the APK’s checksum, application ID, signer and upgrade version code, publishes that exact APK under the version’s GitHub release, and checks that the asset downloads without authentication. It does not rebuild or access the signing key. Bump `versionName` for a new public release instead of replacing a published version. If GitHub does not let the workflow token create a tag for an older tested commit, an authorized maintainer can create the lightweight version tag at that exact commit and retry. The workflow checks the tag before publishing.

## Search the web or this device

- **Sipan Search:** Open the search card on the home page or select **Sipan Search** in the browser menu. Choose **Web**, **Images**, **News**, **Videos**, or **On device**. In a web category, tap **Search with Brave** or press the keyboard’s search key. Choosing a category in the editor or typing never sends the draft. Above results, tap a category to run the same submitted search there, or tap **Edit search** to change the original words rather than editing a URL.
- **Open an image directly:** If Brave’s preview doesn’t respond, tap **Open images directly** above the **Images** results, then tap a picture. Sipan opens the displayed image (sometimes a thumbnail) in the current tab. Go back to return to results, or tap **Cancel** before choosing a picture. This works in regular and private tabs without changing country, Safe Search, or tracker blocking.
- **Search tools:** In **Web**, narrow a search to the past 24 hours, week, month, or year; request an exact phrase or look for PDFs. These are per-search options, not browser-wide defaults. They are restored when editing results from Sipan and do not carry into Images, News, or Videos. Sipan uses Brave’s public time filter and [search operators](https://search.brave.com/help/operators); Brave may show broader results when there are too few matches.
- **Address-bar search:** Type a word or question in the address bar and tap **Use web search** the first time. Subsequent address-bar searches in normal tabs open the public **Brave Search** results page inside Sipan. This uses [Brave’s web index](https://search.brave.com/help/independence), not Google Search or a Sipan crawler, with no API key or account. Brave receives submitted queries as part of normal website navigation. URLs and **Paste & open** still open links directly. Result coverage and ranking depend on Brave and require internet access.
- **Country and Safe Search:** Open **Web search filters** in Sipan Search, above Brave results, or from the browser menu. Choose **Worldwide** or find a country by its English name, Sorani name, or code. Supported countries use Brave’s regional ranking (not a geographic restriction). **Country domains only** requests the country’s top-level domain instead of relying on ranking alone. For regions without a Brave preset, Sipan uses this domain mode automatically (e.g., Iraq uses `site:iq`; the United Kingdom’s domain is `.uk`). That can miss local `.com` sites; Brave may broaden results or show ads and other content outside the domain. This is a search preference, not a change to your connection or IP.
- **Safe Search** defaults to **Moderate**; choose **Strict** or **Off**. Off turns off Brave’s adult-content filter, not Android Safe Browsing, website restrictions, or network blocks. It cannot surface pages outside Brave’s index. Sipan applies the [documented preference cookies](https://search.brave.com/help/anonymous-cookies) to Brave in the current WebView profile before submitting a web query, with automatic IP-based local ranking turned off. Normal settings persist; private-tab settings start at Worldwide/Moderate and expire with the tab. **Apply** refreshes an open Brave results page or uses the new preferences for the next search from Sipan. Changing filters from the local search screen does not contact Brave or enable web search in the address bar.
- **On-device search:** Pick **On device** in Sipan Search or above a web results page. Matches appear as you type from Sipan’s 27-entry starter catalog, bookmarks, recent history and explicitly indexed pages. This works offline and sends no query. To turn off web search in the address bar, choose **Keep on-device search** or turn off **Settings → Web search from the address bar**. A one-off web search from the workspace never changes that preference.
- **Add personal results:** On an eligible loaded page, use **Browser menu → Add page to Sipan Search** to save a local excerpt. Forms, editable fields and hidden text are skipped. Avoid adding sensitive pages. **Settings → Clear pages added to search** removes the excerpts without deleting bookmarks/history.
- **Private tabs and history:** A private address bar always starts with the local starter catalog and cannot add pages. Opening web results from a private tab is an explicit separate action and still sends the query to Brave, in the isolated WebView. Sipan does not add Brave results pages to its persistent History list, although you can go back to them within a tab. Visiting a result is normal browsing.

## Google services and privacy

- **No key required to try it.** The free `gtx` endpoint is unofficial; it can be slow, refuse requests, or change. If it stops working, retry later or use Cloud Translation. Unofficial and official endpoints can have different language coverage.
- **Optional Cloud Translation.** In a Google Cloud project, enable **Cloud Translation API**, enable billing, and create an API key restricted to that API. In **Sipan → Settings → Cloud Translation API key**, enter the key. Sipan uses it automatically for the official v2 API. Google may charge for use. This is **not** the Android signing key.
- **Optional Cloud Vision.** Enable **Cloud Vision API** in Google Cloud, create a restricted key, then add it in **Settings → Cloud Vision API key** and enable **Use Cloud Vision OCR**. This sends the selected image to Google for recognition. Without it, bundled ML Kit and PP-OCRv6 Tiny models read image pixels on the phone. For manga with wrong OCR, try selecting **Japanese**; for manhwa, try **Korean**. The translation source remains Auto unless you explicitly pick **English** or **English comics** for English lettering.
- Nothing is sent to translation providers until you press **Start translation**. If you use on-device OCR, Google Translate gets the recognized text, not the image pixels. On-device search stays local. Optional web search sends the submitted term directly to Brave; Google is still only used for the translation path. The app has no accounts, own backend, or ads. API keys are encrypted with Android Keystore. The app removes ML Kit's bundled CCT telemetry backend registration; Android System WebView still has its own platform services.
- Normal translation strings and rendered images are cached locally. Clear them under **Settings → Clear browser and translation caches**. Private tabs use separate WebView profiles, skip browser history, personal search indexing and translation disk caches, and remove their profile on close (or next launch after an interrupted exit). They do not make browsing or translation anonymous.

## English comics, image OCR and Sorani names

**English (1.8.1)** is a separate choice in **Image text language or script** in Settings and in the image translation sheet. Use it for ordinary English text in photos, menus and signs. It uses the bundled Latin OCR model with English as the translation source, without the comic-specific recognition and layout pass. **English comics** remains the choice for English manga or manhwa. Changing this option does not change the app language, target language, or page-text translation.

For an English-lettered manhwa or comic, open **Translate → Image text language or script → English comics**, keep **Translate images** on, then tap **Start translation**. The same choice is available for a photo from your device. **ئینگلیزی:** لە وەرگێڕاندا **زمان یان جۆری نووسینی وێنە → کۆمیکی ئینگلیزی** هەڵبژێرە و **دەستپێکردن** دابگرە. Use **Japanese** or **Korean** for originals in those languages, not for their English editions.

**Long manhwa strips (1.8).** On-device OCR reads large upright JPEG, PNG and WebP strips as overlapping regions before resizing the image. Most webtoon widths are read at source resolution. It places joins in blank gutters when possible and keeps overlapping context across continuous artwork, so a bubble is read together instead of twice. It fits and places Sorani at the reading scale, then paints onto a bounded display canvas of up to 4.1 million pixels. One large strip is worked on at a time; it doesn't allocate a full-resolution chapter bitmap. Very wide or exceptionally long images are still sampled, and unsupported formats or region decode failures use the normal image path. Cloud Vision remains a separate opt-in path. More detailed scans can take longer than reading a thumbnail. When a tall PNG, JPEG or WebP is embedded as a base64 image on the page, Sipan can read its original bytes in bounded requests instead of taking a small JPEG snapshot. Blob/canvas images or sites that block downloading the source may still be limited to a lower-detail snapshot.

Sipan 1.7 keeps **PP-OCRv6 Tiny** as the fast first pass for horizontal English lettering alongside ML Kit. The enhanced pass looks for enclosed light and dark balloons with unrepresented ink, and re-reads up to five of those crops, rerunning detection only if the ink bands don't already yield a clear line. It uses a **Latin-only derivative of PP-OCRv6 Small** on at most eight uncertain line crops, and keeps Tiny alone on low-RAM devices. The stronger recognizer is about 12.5 MB with its narrowed alphabet. Medium is not bundled: a larger recognizer cannot recover undetected pixels, and running a server-tier model on each panel would cost more size and processing. Tiny now uses smaller tensors for short text, **English comics** skips ML Kit's duplicate detail pass, and fresh gallery results can display the painted bitmap directly. These choices preserve bounded memory and do not imply a speedup on every chapter or phone.

The app groups lines in the same visible enclosure and uses safe blank space in the bubble for RTL layout. If the Sorani response leaves English behind, it retries a bounded number of complete bubbles without batch markers. Short, unambiguous replies such as standalone `YOU?` can use an exact local Sorani fallback without a second network call if the first response leaves it in English. The initial source is English in **English** mode and for English lettering in **English comics** mode; otherwise it is Auto. An English retry requires an explicit choice or enough OCR evidence, not just the hosting page's language. Optional keyed Cloud Vision still replaces local OCR when selected; it is never an automatic fallback.

Detected prices, URLs and IDs are protected. Some text can still remain original (stylized art, outlying text, or a failed translation). The reader and gallery now report known incomplete replacements instead of treating every processed panel as fully translated. Partial renders and suspect translation responses are not saved as completed cache entries. The image-cache namespace was changed, so old partial panels do not prevent a new scan. OCR pixels never leave your device unless you opt into Cloud Vision.

**Enhanced image OCR** is on by default for on-device reading. Sipan scores bundled ML Kit script results by confidence and matching letters, prioritizes Japanese/Korean alternatives in Auto when needed, and can retry up to three small/low-confidence tiles with scaled, contrast-adjusted pixels. The extra bitmap is bounded to about 2.35 megapixels. Detected regions are mapped back to the original image; retry pixels never appear in the saved art. Turn Enhanced image OCR off in the Translate sheet or Settings to skip the targeted rescans and Small refinement. The explicit English comics choice still enables Tiny. Explicit **Japanese** and **Korean** modes are available, including in the gallery. Optional Cloud Vision is unaffected.

When the target is Sorani, an on-device output pass spells common character names that are still in Latin script, e.g. `Naruto` → `ناروتۆ` and `Sung Jin-Woo` → `سونگ جین وو`. It approximates unfamiliar name-like spellings, leaves detected URLs, email addresses, prices, and code-like strings alone, and does not call another translation service. Actual link destinations and the exact original view are unchanged.

## Deviations and known limits

- Sipan uses `evaluateJavascript` to pull small snapshots from an explicitly selected top-level document. There is **no** `@JavascriptInterface` exposed to every frame. Originals are kept in a document-local map so handling inline links and restoring text never requires replacing arbitrary page HTML. Cross-origin iframes, closed shadow DOM, streaming video and JS-only text not accessible in the DOM are not translated. Translation pauses while the tab is hidden or showing the original, and resets on full navigation so a different page isn't translated without consent.
- Manga layout is inferred from OCR line/word geometry, not from a bubble segmentation model. Prices and other numeric-only fields are left in place. White/flat bubbles translate best; angled, stylized, very narrow vertical text and busy backgrounds can be missed. There is no separate bubble segmentation, Manga OCR, or bundled Arabic-script recognition model. Sorani name spellings are approximate; the app does not identify every name or undo names already translated semantically by the provider. Large images use a bounded display bitmap; supported long strips can still be read at a higher resolution in regions. If the translation does not fit legibly, the original region stays in place. Timing depends on the device, image size and network; it isn't a fixed number of seconds.
- Content Security Policy, authentication, hotlink protection and DRM can prevent a native duplicate image request or replacement. Cross-site media fetches omit cookies, unlike eligible same-site fetches. CSS handling targets single background images and canvas handling requires readable, untainted pixels. Some responsive canvases, animations, SVG-only content or unusually virtualized readers may stay untranslated. A data/blob `<img>` is supported when it can be captured locally. The app does not bypass paywalls or anti-bot controls.
- Private tabs require multi-profile support in the installed Android System WebView. If it is unavailable, Sipan doesn't silently reuse the normal profile. Downloads are OS-managed in app-specific storage, and don't forward raw cookies through DownloadManager redirects. Some logged-in downloads may need the site's own workflow or an external app. New views use the selected WebView theme; a page already open when changing the theme may need reopening.
- The app ships 249 Google Translate language choices (public picker codes and names, with native labels). Some variants aren't available on the same schedule on Cloud Translation v2 or the unofficial endpoint. Translation requires an internet connection; bundled OCR itself works locally.

## Develop and verify

Kotlin and Jetpack Compose Material 3, Android System WebView/AndroidX WebKit, Room, DataStore, OkHttp and coroutines. Build with JDK 17, Android SDK Platform 37 and build-tools 36.0.0:

```sh
./gradlew :app:testDebugUnitTest :app:assembleDebug
npm ci --prefix tools/browser-tests --ignore-scripts
npm test --prefix tools/browser-tests
# With an Android device or emulator attached:
./gradlew :app:connectedDebugAndroidTest
```

- **Build Android APK** builds and uploads an installable debug APK after every push and supports manual dispatch. The JVM tests exercise Google response parsing, batching/target selection with a mock web server, OCR layout/quality, local search ranking and private scope, web search URL encoding and filters, and Sorani spelling/protected spans. DOM tests cover consent gating, exact text restoration, dynamic content, responsive images, hold/release, and bounded index extraction.
- **Reader device smoke tests** use Android WebView and the real bundled OCR models with a deterministic test translation provider (not a live Google evaluation). It tests Tiny’s recognition and spacing on a generated English two-bubble fixture, checks the exact text sent per bubble, and verifies the rendered pixels and unchanged price. A higher-resolution 1.7 fixture checks faint text recovery, fused spacing, separate short dialogue, unchanged translations, and protected prices and URLs. A targeted x86_64 Android test also runs on the 16 KiB page-size system image; the APK build checks both 64-bit ONNX libraries and the model hashes. They cover the Sorani controls and consent sheet, search opt-in, live on-device matches, Web/Images/News/Videos navigation, preserving the original query and search tools when editing, changing the country and Safe Search, real cookie stores on WebViews that support isolated profiles, explicit index extraction, the v1 → v2 library migration, exact WebView restoration, image swaps and hold/release, lazy loading, Japanese/Korean OCR, and stationary menu prices. The WebView search tests use a fixture response from the actual navigation path, not a live site returning fixed results.
- For a live end-to-end check on a phone: translate the sample headings into `ckb`, hold the comic image and release it, scroll to the menu and check prices, then try an English article and a chapter you can access. Try the explicit Japanese/Korean OCR models for that chapter. Verify the Google provider can be reached on your network.

### Roadmap / extension points

`web/DocumentFeatures` and `translation/TranslationProvider` / `OcrProvider` are the internal hooks for new browser tools or engines. Web extensions, ad SDK integration, sync, and accounts are deliberately absent. Any future ad SDK would require explicit review and separation from page data. Possible additions: bubble segmentation for difficult lettering and better support for animated or canvas-based readers.

The PP-OCRv6 Tiny assets and [modified Small Latin recognizer](app/src/main/assets/ocr/ppocrv6-small-latin/NOTICE.txt) are pinned locally with Apache 2.0 [license and source notices](app/src/main/assets/ocr/ppocrv6-tiny/NOTICE.txt). ONNX Runtime 1.30.0 uses the MIT license and [upstream third-party notices](app/src/main/assets/ocr/onnxruntime/) shipped with the binary distribution. The universal APK uses compressed native libraries to reduce the download; Android extracts the matching ABI when installing.

The bundled Noto Naskh Arabic font license is in `app/src/main/assets/noto-naskh-ofl.txt`. The country names come from [Unicode CLDR 49](https://github.com/unicode-org/cldr-json), with the license bundled in `app/src/main/assets/cldr-license.txt`. The comic and menu assets are original test fixtures; their generator is under `tools/`.
