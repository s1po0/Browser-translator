# Extension stores in Sipan

Open **Menu → Extension stores** (also in **Settings → Browsing**). Pick **Add Keiyoushi** or paste a catalog address into **Add a store**. **Check address** fetches a preview; **Add store** saves it on this device. Stores are not added automatically. Refresh fetches the catalog again; removing it forgets the address and signing fingerprint, not any APK installed by Android. A store needs a connection to load. Catalog searches are local, over extension names, source names, and language codes (for example, `manga en`). Mixed, adult, and unrated entries are hidden until you turn on their filter.

**Open website** opens the published source homepage in Sipan's normal browser, where web translation can be used. It does not run the source or fetch its chapter list. **Verify and install APK** instead downloads a separately signed package for compatible Android readers. Sipan checks it, then hands it to Android's installer. You may need to explicitly allow installs from Sipan in Android Settings and return to confirm; no install is started automatically.

## What the upstream repositories actually serve

| Layer | Observed upstream behavior |
| --- | --- |
| Add-store link | [Mihon v0.21.3 `MainActivity`](https://github.com/mihonapp/mihon/blob/feadad5e1e2bf638be6e2ca317d11657b09d4596/app/src/main/java/eu/kanade/tachiyomi/ui/main/MainActivity.kt#L645-L672) reads the `url` parameter in `mihon://extension-store` and `tachiyomi://add-repo`. Both link forms can be pasted into Sipan; Sipan does not register as their system link handler. |
| Store index | [Mihon's service](https://github.com/mihonapp/mihon/blob/feadad5e1e2bf638be6e2ca317d11657b09d4596/data/src/main/java/mihon/data/extension/service/ExtensionStoreService.kt) sniffs gzip, distinguishes Protobuf and JSON, and supports inline and split extension lists. It resolves older `index.min.json` addresses through `repo.json`; `index_v2` points to the new catalog when present. Sipan supports these formats over HTTPS. True legacy stores need `repo.json` with a signing fingerprint. |
| Keiyoushi publication | The [published `repo` snapshot](https://github.com/keiyoushi/extensions/tree/86753ebff0e21195dedca7a5edd2162240093d08) advertises **`https://github.com/keiyoushi/extensions/raw/repo/index.pb`**. The pinned snapshot has 1,711 entries, including 632 marked safe. `index.pb` is gzipped Protobuf; `index.json` represents the modern index in JSON. The legacy `index.min.json` has two app-update placeholders, not the catalog. Its sibling `repo.json` points to `index.pb`. |
| Extension artifact | The [Keiyoushi schema](https://github.com/keiyoushi/extensions-source/blob/8947c372cd87f546a0b80cb0e4b0a5a8add5ef88/.github/scripts/index.proto) provides an APK URL and an independent JAR URL. Its [publisher](https://github.com/keiyoushi/extensions-source/blob/8947c372cd87f546a0b80cb0e4b0a5a8add5ef88/.github/scripts/publish-repo.py) puts APKs in GitHub Release assets; use their listed URL, not a guessed `/apk/` path. For example, the pinned `MANGA Plus by SHUEISHA` entry advertises version `1.6.69` and Android versionCode `106069` in release `8947c37`. |
| Trust and loading | [Mihon's installer](https://github.com/mihonapp/mihon/blob/feadad5e1e2bf638be6e2ca317d11657b09d4596/app/src/main/java/eu/kanade/tachiyomi/extension/util/ExtensionInstaller.kt) checks APK signing certificates against the store key. Its [loader](https://github.com/mihonapp/mihon/blob/feadad5e1e2bf638be6e2ca317d11657b09d4596/app/src/main/java/eu/kanade/tachiyomi/extension/util/ExtensionLoader.kt) checks the manifest, API version (`1.4`/`1.6` in this version), and trust, then loads the declared `Source` or `SourceFactory` via a class loader. This step is separate from fetching an index or installing the APK. |

Sipan accesses catalogs and APKs through a separate HTTPS client with no browser cookies. Keiyoushi's preset pins the publisher's SHA-256 certificate fingerprint. For other stores, the user reviews and accepts the reported fingerprint; a matching fingerprint on refresh does **not** independently authenticate the catalog, which is still HTTPS content from that publisher. Catalog downloads and decompressed payloads are bounded; external icons and JARs are not fetched. Before handoff, Android's archive parser must return a single signer matching the accepted fingerprint, a package and version matching the entry, and the expected extension feature and source manifest metadata. Redirects never downgrade to HTTP. A signing-key change is blocked rather than silently trusted.

## What would be needed to run the sources

The index contains names, language codes, resources, and home URLs, not titles, chapter lists, or page images. [Mihon's `CatalogueSource`](https://github.com/mihonapp/mihon/blob/feadad5e1e2bf638be6e2ca317d11657b09d4596/source-api/src/main/kotlin/eu/kanade/tachiyomi/source/CatalogueSource.kt) and [`HttpSource`](https://github.com/mihonapp/mihon/blob/feadad5e1e2bf638be6e2ca317d11657b09d4596/source-api/src/main/kotlin/eu/kanade/tachiyomi/source/online/HttpSource.kt) define host-side search, manga details, chapters, pages, image fetching, and injected networking. The [Keiyoushi build](https://github.com/keiyoushi/extensions-source/blob/8947c372cd87f546a0b80cb0e4b0a5a8add5ef88/gradle/build-logic/src/main/kotlin/io/github/keiyoushi/gradle/tasks/GenerateManifestTask.kt) declares a generated source class. Some sources also depend on source settings, host preferences, or custom network clients. Sipan's browser WebView exposes none of this API. A native runtime would need compatible APIs and dependencies, a trust and execution-isolation design for third-party code, and a reader that integrates chapter/page results with OCR. This feature does not add that runtime, auto-updates, or cross-source title search.

## Tests

`StoreCatalogReaderTest` uses a 766-byte gzip fixture derived from the pinned Keiyoushi Protobuf by filtering its entries to the safe MANGA Plus and Webtoons.com records and serializing with Keiyoushi's generated Python bindings. The two entries retain the real APK and JAR field numbers and URLs. Other tests cover split and legacy catalogs, unwrapping links, warnings, redirected TLS downgrade, size limits, and changed signing fingerprints. The Android smoke tests exercise the store UI, DataStore, and Android's signed-archive verification and scoped content URI using the instrumentation APK as a benign fixture. They do not install a live Keiyoushi download, request arbitrary app-install permissions, or execute an extension.
